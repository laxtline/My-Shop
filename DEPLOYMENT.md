# Production deployment runbook

This is the shortest path from this repository to a working shop:

| Piece | Host | Cost |
|---|---|---|
| API (`Website/backend`) | Render (Node) | Free to start, ~$7/mo recommended |
| Database | MongoDB Atlas | Free M0 |
| Website (`Website/frontend`) | Vercel | Free |
| Android/iOS app (`MobileApp`) | Expo EAS | Free builds, store fees apply |

Deploy in this order: **Atlas → API → website → integrations → mobile**.
Each step ends with a value the next step needs.

---

## 0. Accounts you need

- [ ] GitHub (repo already pushed to `laxtline/My-Shop`)
- [ ] [MongoDB Atlas](https://cloud.mongodb.com)
- [ ] [Render](https://render.com) (or Railway / a VPS)
- [ ] [Vercel](https://vercel.com)
- [ ] [Razorpay](https://dashboard.razorpay.com) — only for online payments
- [ ] [Shiprocket](https://app.shiprocket.in) — only for real couriers
- [ ] [Resend](https://resend.com) — only for order emails
- [ ] [Google Cloud Console](https://console.cloud.google.com) — Google sign-in
- [ ] [Expo](https://expo.dev) + Google Play / Apple Developer — mobile stores

Without Razorpay, Shiprocket or Resend the shop still runs: COD works, delivery
estimates are zone-based, and emails are logged to the console. The API will
refuse to boot without `MONGODB_URI`, `JWT_SECRET` and `GOOGLE_CLIENT_ID`.

## 1. MongoDB Atlas

1. Create a free **M0** cluster (region: Mumbai / Singapore).
2. **Database Access** → add a user with a strong password.
3. **Network Access** → allow `0.0.0.0/0` (Render's outbound IPs are dynamic).
4. **Connect → Drivers** → copy the URI and append the database name:

```text
mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/ramachandra?retryWrites=true&w=majority
```

Transactions (order + stock updates) need a replica set. Atlas clusters are
replica sets, so this works out of the box.

## 2. API on Render

1. Push this repo (including `render.yaml`).
2. Render Dashboard → **New → Blueprint** → select the repo.
3. Render creates `ramachandra-traders-api` from `render.yaml`.
4. Fill every `sync: false` variable in **Environment**:

### Required

| Variable | Value |
|---|---|
| `MONGODB_URI` | Atlas URI from step 1 |
| `CLIENT_ORIGIN` | Vercel URL(s), e.g. `https://my-shop.vercel.app` (comma separated, no trailing slash). You can add the final domain after step 3 and redeploy. |
| `GOOGLE_CLIENT_ID` | Web OAuth client id from step 8 |
| `PUBLIC_API_URL` | `https://ramachandra-traders-api.onrender.com` |

### Recommended

| Variable | Value |
|---|---|
| `GOOGLE_MOBILE_CLIENT_IDS` | iOS + Android client ids (comma separated) |
| `MOBILE_PAYMENT_RETURN_URL` | `https://<website-domain>/orders` |
| `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` | Razorpay live keys |
| `RAZORPAY_WEBHOOK_SECRET` | random secret, same value in the Razorpay dashboard |
| `RESEND_API_KEY` / `EMAIL_FROM` | e.g. `Ramachandra Traders <orders@yourdomain.com>` |
| `SHIPROCKET_EMAIL` / `SHIPROCKET_PASSWORD` | Shiprocket API login |
| `SHIPROCKET_PICKUP_LOCATION` | pickup nickname created in Shiprocket |
| `SHIPROCKET_WEBHOOK_TOKEN` | shared secret for the carrier webhook |

`JWT_SECRET` and `REFUND_ENCRYPTION_KEY` are generated by Render from
`render.yaml`. Do not rotate `REFUND_ENCRYPTION_KEY` after refunds exist.

5. Wait for the deploy, then open:

```text
https://<api-domain>/api/health   →  {"success":true,"data":{"status":"ok",...}}
```

6. Seed the catalogue once (Render Shell):

```bash
npm run seed
```

`productSeed.ts` deletes existing products and categories before inserting, so
never run it on a live catalogue.

### Uploads

Product and category images accept **ImageKit** and **Cloudinary** delivery
URLs out of the box, and the brand logo accepts any HTTPS image URL. Pasting
CDN URLs into the admin forms is the recommended setup for a hosted deploy.

Admin file uploads (`POST /api/uploads`) are still written to
`Website/backend/uploads` on local disk. Render's disk is ephemeral unless you
attach a **persistent disk** (paid plans) at
`/opt/render/project/src/Website/backend/uploads`; Railway needs a volume. If
you use CDN URLs, you never need that disk.

### Railway instead of Render

```bash
railway login
railway init
railway up            # root Dockerfile is used
railway variables     # add the same variables
```

Add a public domain under **Settings → Networking**.

## 3. Website on Vercel

1. Vercel → **Add New → Project** → import `laxtline/My-Shop`.
2. **Root Directory**: `Website/frontend` (framework auto-detects Next.js).
3. Environment variables (Production, and Preview if you use previews):

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_API_URL` | `https://<api-domain>` |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | same web client id as the API |
| `NEXT_PUBLIC_SITE_URL` | `https://<website-domain>` |

4. Deploy, then copy the production URL (e.g. `https://my-shop.vercel.app`).
5. Add that URL to the API's `CLIENT_ORIGIN` and redeploy the API. Login,
   cookies and checkout will 403 until this matches exactly.
6. Optional: **Settings → Domains** → add `www.your-shop.in`, point DNS at
   Vercel, and add the custom domain to `CLIENT_ORIGIN` too.

CLI alternative (already logged in on this machine):

```bash
cd Website/frontend
vercel link
vercel env add NEXT_PUBLIC_API_URL production
vercel env add NEXT_PUBLIC_GOOGLE_CLIENT_ID production
vercel env add NEXT_PUBLIC_SITE_URL production
vercel --prod
```

## 4. Razorpay (online payments)

1. Complete KYC and switch the dashboard to **Live**.
2. **Settings → API Keys** → generate live keys → set `RAZORPAY_KEY_ID` and
   `RAZORPAY_KEY_SECRET` on the API, then redeploy.
3. **Settings → Webhooks** → add:

```text
https://<api-domain>/api/payments/razorpay/webhook
```

Secret: the same value as `RAZORPAY_WEBHOOK_SECRET`.
Events: `payment.captured`, `payment.failed`, `order.paid`, `payment_link.paid`,
`refund.processed` (add `refund.failed` if listed).

4. Test with a ₹1 live order (UPI + card + netbanking), then refund it.
5. Mobile links return to `MOBILE_PAYMENT_RETURN_URL`; Razorpay rejects custom
   app schemes, so it must be an `https://` page.

---

## 5. Couriers (Shiprocket recommended)

1. Create the pickup address in Shiprocket → **Settings → Pickup Addresses**.
2. Use the same nickname in `SHIPROCKET_PICKUP_LOCATION`.
3. Set `SHIPROCKET_EMAIL` / `SHIPROCKET_PASSWORD` on the API.
4. **Settings → Webhooks**:

```text
https://<api-domain>/api/shipping/webhook/shiprocket
```

Add header `x-webhook-token: <SHIPROCKET_WEBHOOK_TOKEN>`.

5. In **Admin → Shipping → Settings**, confirm warehouse pincode, COD fee,
   free-delivery threshold and courier preference.
6. Place a test order, open **Admin → Shipments**, create the shipment, then
   use **Sync** to pull the AWB and tracking events. Shiprocket reaches Ekart,
   Delhivery, Blue Dart, DTDC, XpressBees and Shadowfax with one credential.

Direct Delhivery is the alternative: `DELHIVERY_API_TOKEN`,
`DELHIVERY_PICKUP_LOCATION`, `DELHIVERY_CLIENT_NAME`, `DELHIVERY_WEBHOOK_TOKEN`,
webhook `https://<api-domain>/api/shipping/webhook/delhivery`.

---

## 6. Email (Resend)

1. Add and verify your domain in Resend (SPF + DKIM DNS records).
2. Create an API key → `RESEND_API_KEY`.
3. `EMAIL_FROM` must use the verified domain, e.g.
   `Ramachandra Traders <orders@your-shop.in>`.
4. Place an order and confirm the confirmation email arrives.

---

## 7. Google sign-in

1. Google Cloud → **APIs & Services → Credentials**.
2. **Web client** (for the website + API verification):
   - Authorized JavaScript origins: `https://<website-domain>`
   - Authorized redirect URIs: `https://<website-domain>`
3. Use the same id for `GOOGLE_CLIENT_ID` and `NEXT_PUBLIC_GOOGLE_CLIENT_ID`.
4. Mobile: create **iOS** and **Android** OAuth clients with the bundle/package
   `com.ramachandratraders.app`. Put both ids in `GOOGLE_MOBILE_CLIENT_IDS` and
   in the mobile env (`EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`,
   `EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID`).
5. Android needs the release SHA-1 from EAS:
   `eas credentials` → Android → Keystore → SHA-1 fingerprint.

---

## 8. Mobile apps (Expo EAS)

1. `npm i -g eas-cli && eas login`
2. In `MobileApp/`: `eas init` (creates the project and prints a project id).
3. Put that id into `app.json` → `expo.extra.eas.projectId` (or set
   `EAS_PROJECT_ID` in the build environment).
4. Edit `eas.json` and replace the placeholders in `preview` and `production`:

```json
"EXPO_PUBLIC_API_URL": "https://<api-domain>",
"EXPO_PUBLIC_STOREFRONT_URL": "https://<website-domain>"
```

5. Build:

```bash
eas build -p android --profile production    # .aab
eas build -p ios --profile production        # needs Apple Developer account
```

6. Submit: `eas submit -p android` / `eas submit -p ios`, or upload manually.
7. For push notifications set `EXPO_PUSH_ENABLED=true` on the API and upload
   the FCM/APNs credentials with `eas credentials`.

## 9. Go-live checklist

- [ ] `https://<api>/api/health` returns `status: ok`
- [ ] `https://<api>/api/products` returns the seeded catalogue
- [ ] Website home, product, search, cart load over HTTPS
- [ ] Google sign-in works on the deployed domain (not just localhost)
- [ ] COD order end-to-end; admin records cash collection
- [ ] Online order captured; Razorpay webhook shows `200` in the dashboard
- [ ] Refund from Admin → Orders succeeds
- [ ] Shipment created, AWB + tracking visible to the customer
- [ ] Confirmation email delivered
- [ ] Mobile app loads products over the public API
- [ ] `CLIENT_ORIGIN` contains every live browser origin
- [ ] Atlas backup enabled and a restore has been tested

---

## 10. Operations notes

- **Free Render instance sleeps** after inactivity. Upgrade to `starter` for a
  production shop, or keep a small uptime ping (not a substitute for paid).
- **Logs**: Render → Logs; Vercel → Deployment → Functions/Logs.
- **Migrations**: none — Mongoose creates collections. Seed/import products
  through the admin UI instead of re-running destructive seeds.
- **Backups**: Atlas M0 has no continuous backups; take `mongodump` snapshots
  or upgrade before real customer data accumulates.
- **Secrets**: keep `.env` files out of git (already ignored). Rotate exposed
  keys immediately.
- **Do not run `npm run seed` on production** after launch.
