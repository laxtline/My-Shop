================================================================================
  RAMACHANDRA TRADERS — DEPLOY / GO-LIVE GUIDE (Level 4)
================================================================================
  Free stack:  MongoDB Atlas (database) + Render (backend) + Vercel (frontend).
  Time: ~30-45 min the first time. Follow top to bottom.

  This guide is CURRENT — it includes every env var added through Levels 1-3
  (Razorpay, Resend email, SITE_URL). Do the two typecheck commands in STEP 0
  first so you deploy known-good code.
================================================================================


--------------------------------------------------------------------------------
  STEP 0 — VERIFY LOCALLY FIRST (do this before deploying)
--------------------------------------------------------------------------------
  # Backend compiles + all tests pass:
  cd "Website/backend"
  npm install
  npm run typecheck
  npm run test:smoke        # should end with "✅ ALL PASSED"

  # Frontend compiles:
  cd "../frontend"
  npm install
  npm run typecheck
  npm run build             # a successful production build

  If anything fails, fix it (or send me the error) BEFORE deploying.


--------------------------------------------------------------------------------
  STEP 1 — DATABASE: MongoDB Atlas (free M0)
--------------------------------------------------------------------------------
  1. Sign up at https://www.mongodb.com/atlas  -> create a FREE "M0" cluster.
  2. Database Access -> Add a user (username + password). Save them.
  3. Network Access -> Add IP -> "Allow access from anywhere" (0.0.0.0/0).
  4. Clusters -> Connect -> Drivers -> copy the connection string. Looks like:
       mongodb+srv://USER:PASSWORD@cluster0.xxxx.mongodb.net/ramachandra
     Put your real user/password in it and add "/ramachandra" as the db name.
     -> This is your MONGODB_URI.


--------------------------------------------------------------------------------
  STEP 2 — GOOGLE OAUTH (login)
--------------------------------------------------------------------------------
  1. https://console.cloud.google.com -> APIs & Services -> Credentials.
  2. Create an OAuth 2.0 Client ID (type: Web application).
  3. Authorized JavaScript origins — add BOTH now (edit after you know the URLs):
       http://localhost:3000
       https://YOUR-SITE.vercel.app         (add once Vercel gives you the URL)
  4. Copy the Client ID -> this is GOOGLE_CLIENT_ID (same value front + back).
     (No client secret is needed — the app verifies Google ID tokens.)


--------------------------------------------------------------------------------
  STEP 3 — BACKEND: Render (free web service)
--------------------------------------------------------------------------------
  Option A (easiest) — Blueprint:
    1. Push this repo to GitHub.
    2. Render.com -> New + -> Blueprint -> pick the repo. It reads render.yaml.
    3. When prompted, fill the secrets (see env list below).

  Option B — Manual:
    1. Render -> New + -> Web Service -> connect the repo.
    2. Root Directory:  Website/backend
       Build Command:   npm install
       Start Command:   npm start
       Health Check:    /api/health
    3. Add the environment variables below.

  BACKEND ENV VARS (Render dashboard):
    NODE_ENV        = production
    PORT            = (leave blank — Render sets it automatically)
    CLIENT_ORIGIN   = https://YOUR-SITE.vercel.app     (no trailing slash)
    MONGODB_URI     = (from STEP 1)
    JWT_SECRET      = (long random string; Blueprint auto-generates one)
    JWT_EXPIRES_IN  = 7d
    GOOGLE_CLIENT_ID= (from STEP 2)
    # Optional — leave blank to disable that feature:
    RAZORPAY_KEY_ID     = (Razorpay Test/Live key id)   -> enables online payment
    RAZORPAY_KEY_SECRET = (Razorpay key secret)
    RESEND_API_KEY      = (Resend API key)              -> enables order emails
    EMAIL_FROM          = Ramachandra Traders <orders@yourdomain.com>

  4. Deploy. When live you get a URL like https://ramachandra-traders-api.onrender.com
     Test it:  open  <that URL>/api/health  -> should show {"success":true,...}

  SEED THE DATABASE (one time — loads branding + 72 demo products):
    Easiest: run it locally pointed at Atlas —
       cd Website/backend
       # temporarily put your Atlas MONGODB_URI in .env, then:
       npm run seed
    (Or use Render's "Shell" tab on the service and run: npm run seed)

  NOTE (free tier): Render free services sleep after ~15 min idle; the first
  request then takes ~30-60s to wake. Also the /uploads folder is EPHEMERAL on
  free hosting (uploaded images are lost on restart/redeploy). For permanent
  product images, paste image URLs, or add Cloudinary later. The rest of the app
  is unaffected.


--------------------------------------------------------------------------------
  STEP 4 — FRONTEND: Vercel
--------------------------------------------------------------------------------
  1. Vercel.com -> Add New -> Project -> import the repo.
  2. Root Directory:  Website/frontend
     Framework preset: Next.js (auto-detected). Build/Output: defaults are fine.
  3. Environment Variables:
       NEXT_PUBLIC_API_URL          = https://ramachandra-traders-api.onrender.com
       NEXT_PUBLIC_GOOGLE_CLIENT_ID = (same Client ID as the backend)
       NEXT_PUBLIC_SITE_URL         = https://YOUR-SITE.vercel.app
  4. Deploy. Vercel gives you https://YOUR-SITE.vercel.app


--------------------------------------------------------------------------------
  STEP 5 — WIRE THE TWO TOGETHER (important!)
--------------------------------------------------------------------------------
  Now that you know the real URLs, update these and redeploy:
    - Render backend:  CLIENT_ORIGIN = your exact Vercel URL (no trailing slash).
    - Google console:  add your Vercel URL to Authorized JavaScript origins.
    - Vercel:          NEXT_PUBLIC_SITE_URL + NEXT_PUBLIC_API_URL are correct.
  Redeploy backend (Render) and frontend (Vercel) after changing env vars.

  Cross-site cookies are already handled: in production the auth cookie is sent
  with Secure + SameSite=None (see backend authController), which is required
  because the frontend (Vercel) and backend (Render) are on different domains.

--------------------------------------------------------------------------------
  COMMON ISSUES
--------------------------------------------------------------------------------
  - Login fails / CORS error: CLIENT_ORIGIN (Render) must EXACTLY match the
    Vercel URL, no trailing slash. And the Vercel URL must be in Google's
    Authorized JavaScript origins. Redeploy after changing.
  - "Not authenticated" right after login: usually the cookie is blocked because
    NODE_ENV isn't "production" on Render (Secure/SameSite=None needs it).
  - Products don't load: backend not seeded (run npm run seed) or MONGODB_URI wrong.
  - First request very slow: Render free tier waking from sleep — normal.
