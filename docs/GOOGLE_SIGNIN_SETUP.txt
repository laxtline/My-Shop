===============================================================================
GOOGLE SIGN-IN SETUP — EXTERNAL STEPS
Ramachandra Traders
===============================================================================

This file covers everything that happens OUTSIDE the project code — the work you
do in a browser on Google's website. None of this is in the repo, and none of it
can be automated from the codebase.

The project code for Google Sign-In is already finished. What is missing is the
Google-side configuration that authorizes your specific URLs and users.

-------------------------------------------------------------------------------
READ THIS FIRST — MOST LIKELY CAUSE OF YOUR CURRENT ERROR
-------------------------------------------------------------------------------

Your frontend was moved from port 3000 to port 3001 during local testing
(port 3000 was already taken by another project).

Google validates the EXACT origin the login request comes from. If your Google
Cloud Console lists only:

    http://localhost:3000

...then a login attempt from http://localhost:3001 is rejected. Google shows a
generic "policy violation" / "Access blocked" style message that does not name
the port, which makes this confusing to diagnose.

TWO WAYS TO FIX — pick one:

  Option A (recommended, no Google changes needed)
    Free up port 3000 and run the storefront there instead.
    - Close the other app using port 3000, then:
        cd Website/frontend
        npm run dev
    - Confirm it says "Local: http://localhost:3000"

  Option B (keep port 3001)
    Add http://localhost:3001 to Authorized JavaScript origins in Google Cloud
    Console (see STEP 5 below). Changes can take a few minutes to apply.

Also confirm the frontend env matches whichever port you use:
    Website/frontend/.env.local  ->  NEXT_PUBLIC_SITE_URL=http://localhost:3000

-------------------------------------------------------------------------------
WHAT YOU NEED BEFORE STARTING
-------------------------------------------------------------------------------

  - A Google account (any Gmail account works)
  - 15-20 minutes
  - Your local URLs: http://localhost:3000 (frontend), http://localhost:5000 (API)
  - Your deployed URLs, if you have already deployed (Vercel / Render)

Cost: free. Google OAuth for a normal web app has no charge.

===============================================================================
STEP 1 — CREATE A GOOGLE CLOUD PROJECT
===============================================================================

  1. Go to:  https://console.cloud.google.com/
  2. Sign in with your Google account.
  3. Click the project dropdown at the top of the page (next to the Google Cloud
     logo).
  4. Click "New Project".
  5. Project name:  Ramachandra Traders
     Organization / Location: leave as "No organization" if offered.
  6. Click "Create". Wait a few seconds.
  7. IMPORTANT: after it is created, use the project dropdown again and make sure
     "Ramachandra Traders" is the ACTIVE project. Every later step applies to the
     currently selected project — this is the single most common place people go
     wrong.

===============================================================================
STEP 2 — OPEN THE GOOGLE AUTH PLATFORM / OAUTH CONSENT SCREEN
===============================================================================

Google has been renaming and reorganising this section, so you may see either
the older "OAuth consent screen" page or the newer "Google Auth Platform"
page. Both do the same thing.

  1. In the left sidebar, go to:
        APIs & Services  ->  OAuth consent screen
     (Newer console: search "Google Auth Platform" in the top search bar.)

  2. If you are asked to "Get started" or configure the project, do so.

  3. Choose the user type:

        External   <-- CHOOSE THIS

     "Internal" is only available if you have a Google Workspace organization,
     and it would restrict sign-in to your own company domain. For a public
     store, you want External.

  4. Click "Create" / "Next".

===============================================================================
STEP 3 — FILL IN THE APP INFORMATION
===============================================================================

Fill these fields. Anything not listed can be left blank.

  App name:              Ramachandra Traders
  User support email:    ramachandratraders2000@gmail.com
                         (or your own email — must be one you can access)

  App logo:              OPTIONAL. Skip it for now.
                         WARNING: uploading a logo triggers Google's brand
                         verification review, which can take days or weeks. Do
                         not upload a logo until you actually need it.

  Application home page:      http://localhost:3000
                              (later: your deployed Vercel URL)
  Application privacy policy: leave blank for now
  Application terms of service: leave blank for now

  Authorized domains:    Leave EMPTY while you are only testing on localhost.
                         Google does not accept "localhost" here.
                         After deploying, add your bare domain, for example:
                              vercel.app
                         or your own custom domain:
                              ramachandratraders.com
                         Enter the DOMAIN ONLY — no https://, no path,
                         no www prefix.

  Developer contact information:
                         Your email address. This is required.

Click "Save and Continue".

===============================================================================
STEP 4 — SCOPES
===============================================================================

  1. You will land on a "Scopes" page.
  2. Click "Add or Remove Scopes".
  3. Select these three — they are non-sensitive and require NO Google review:

        .../auth/userinfo.email      (See your primary email address)
        .../auth/userinfo.profile    (See your personal info: name, photo)
        openid                       (Associate you with your personal info)

  4. Click "Update", then "Save and Continue".

DO NOT add any other scopes. Anything beyond these three is classified as
"sensitive" or "restricted" by Google and will force your app into a manual
verification process that takes weeks and requires a privacy policy, a demo
video, and a security assessment. This project only needs the user's name,
email, and profile picture.

===============================================================================
STEP 5 — CREATE THE OAUTH CLIENT ID  (THE MOST IMPORTANT STEP)
===============================================================================

  1. In the left sidebar go to:
        APIs & Services  ->  Credentials

  2. Click "+ Create Credentials" at the top, then choose:
        OAuth client ID

  3. Application type:
        Web application        <-- MUST be this exact type

     Do NOT pick "Android", "iOS", or "Desktop app". Those client types cannot
     be used by a browser-based web app and will fail.

  4. Name:  Ramachandra Traders Web

  5. AUTHORIZED JAVASCRIPT ORIGINS
     Click "+ Add URI" for each entry. Add every URL the site is served from:

        http://localhost:3000
        http://localhost:3001        (only if you kept the 3001 port)

     After you deploy, come back and also add:

        https://your-app.vercel.app
        https://ramachandratraders.com      (your custom domain, if any)
        https://www.ramachandratraders.com  (the www version too, if used)

     RULES — Google is strict and unforgiving here:
       - NO trailing slash.        http://localhost:3000/     is INVALID
       - NO path.                  http://localhost:3000/login is INVALID
       - Port matters.             :3000 and :3001 are different origins
       - Protocol matters.         http:// and https:// are different origins
       - www matters.              example.com and www.example.com are different
       - http:// is allowed ONLY for localhost. Every other domain must be https

  6. AUTHORIZED REDIRECT URIS
     Leave this EMPTY.

     This project uses Google Identity Services via the @react-oauth/google
     library. Google returns an ID token directly to the page in JavaScript —
     there is no server-side redirect callback. Adding redirect URIs here is
     harmless but unnecessary. If you leave the JavaScript origins blank and
     fill only redirect URIs, sign-in will NOT work.

  7. Click "Create".

  8. A dialog appears showing:

        Client ID:      639886134229-xxxxxxxxxxxx.apps.googleusercontent.com
        Client Secret:  GOCSPX-xxxxxxxxxxxxxxxxx

     COPY THE CLIENT ID. That is the value the project needs.

     You do NOT need the Client Secret for this project. The backend verifies
     Google's ID token using only the Client ID. Never commit the secret
     anywhere.

===============================================================================
STEP 6 — ADD TEST USERS  (CRITICAL WHILE THE APP IS UNPUBLISHED)
===============================================================================

A new External app starts in "Testing" publishing status. In Testing mode, ONLY
email addresses you explicitly whitelist can sign in. Everyone else gets an
"Access blocked" / policy error — even you, if your address is not listed.

  1. Go to:  APIs & Services  ->  OAuth consent screen
     (newer console: Google Auth Platform -> Audience)
  2. Find the "Test users" section.
  3. Click "+ Add Users".
  4. Add every email that needs to log in during development:
        - your own Gmail address
        - ramachandratraders2000@gmail.com
        - any friend, client, or reviewer who will try the site
  5. Click "Save".

Limits in Testing mode:
  - Maximum 100 test users
  - Tokens expire after 7 days, so testers must re-login weekly
  - This is fine for development and for showing a demo

===============================================================================
STEP 7 — PUT THE CLIENT ID INTO THE PROJECT
===============================================================================

The SAME Client ID goes in two places. They must match exactly, or the backend
will reject every token the frontend sends.

  FILE 1:  Website/frontend/.env.local

      NEXT_PUBLIC_GOOGLE_CLIENT_ID=639886134229-xxxx.apps.googleusercontent.com

  FILE 2:  Website/backend/.env

      GOOGLE_CLIENT_ID=639886134229-xxxx.apps.googleusercontent.com

After editing, RESTART BOTH SERVERS. Environment variables are read once at
startup — editing the file while the server runs changes nothing.

      # Terminal 1
      cd Website/backend
      npm run dev

      # Terminal 2
      cd Website/frontend
      npm run dev

Note: NEXT_PUBLIC_ variables are embedded into the browser bundle and are
publicly visible. That is expected and safe — a Google Client ID is not a
secret. The Client SECRET is a secret, and this project never uses it.

===============================================================================
STEP 8 — TEST IT
===============================================================================

  1. Open http://localhost:3000 in the browser.
  2. Click Sign in.
  3. The Google button should render. If you see a "configuration missing"
     message instead, NEXT_PUBLIC_GOOGLE_CLIENT_ID is not set or the frontend
     was not restarted.
  4. Choose your Google account.
  5. You should be returned to the store, signed in, with your name and profile
     photo visible in the header.

If it fails, open the browser DevTools Console (F12) and read the actual error
text. Google's on-screen message is deliberately vague; the console error is
specific.

===============================================================================
COMMON ERRORS AND WHAT THEY ACTUALLY MEAN
===============================================================================

ERROR: "Access blocked: this app's request is invalid"
ERROR: "doesn't comply with Google's OAuth 2.0 policy"
ERROR: Error 400: redirect_uri_mismatch
ERROR: Error 400: origin_mismatch
  CAUSE: The URL in the address bar is not in Authorized JavaScript Origins.
  FIX:   Go to Credentials -> your OAuth client -> check the origin character by
         character. Watch for: wrong port, trailing slash, http vs https,
         missing www, 127.0.0.1 instead of localhost (they are NOT the same to
         Google — always use localhost).
  NOTE:  Changes can take 5 minutes to a few hours to propagate. Try an
         incognito window to rule out caching.

ERROR: "Access blocked: Ramachandra Traders has not completed the Google
        verification process"
  CAUSE: App is in Testing mode and your email is not a test user.
  FIX:   Add the email under Test users (STEP 6). Or publish the app (see below).

ERROR: "This app is blocked" / admin policy error
  CAUSE: You are using a Google Workspace (company/school) account whose
         administrator blocks third-party apps.
  FIX:   Use a personal @gmail.com account instead.

ERROR: idpiframe_initialization_failed
  CAUSE: Third-party cookies are blocked in the browser.
  FIX:   Allow third-party cookies for accounts.google.com, or test in a
         different browser. Chrome Incognito blocks these by default.

ERROR: The Google button does not appear at all
  CAUSE: NEXT_PUBLIC_GOOGLE_CLIENT_ID is empty, or the frontend was not
         restarted after editing .env.local.
  FIX:   Restart npm run dev. Confirm the value with: echo the variable, or
         check the login dialog message.

ERROR: Login works but backend returns 401 Unauthorized
  CAUSE: GOOGLE_CLIENT_ID in the backend .env does not match the frontend one.
  FIX:   Make both identical, restart the backend.

ERROR: CORS error in the console after clicking sign in
  CAUSE: Backend CLIENT_ORIGIN does not include the frontend URL.
  FIX:   In Website/backend/.env set (comma-separated, no spaces, no trailing
         slash):
             CLIENT_ORIGIN=http://localhost:3000,http://localhost:3001
         Restart the backend.

===============================================================================
GOING TO PRODUCTION
===============================================================================

When you deploy to Vercel + Render, do all of the following:

  1. GOOGLE CLOUD CONSOLE
     Credentials -> your OAuth client -> Authorized JavaScript origins:
     add your live HTTPS URL(s):
             https://your-app.vercel.app
             https://ramachandratraders.com
             https://www.ramachandratraders.com

     OAuth consent screen -> Authorized domains:
     add the bare domain (no https://, no path):
             vercel.app
        or   ramachandratraders.com

  2. VERCEL (frontend environment variables)
             NEXT_PUBLIC_GOOGLE_CLIENT_ID = <same client id>
             NEXT_PUBLIC_API_URL          = https://your-backend.onrender.com
             NEXT_PUBLIC_SITE_URL         = https://your-app.vercel.app
     Redeploy after adding these — Vercel bakes NEXT_PUBLIC_ vars at build time.

  3. RENDER (backend environment variables)
             GOOGLE_CLIENT_ID = <same client id>
             CLIENT_ORIGIN    = https://your-app.vercel.app
     For multiple domains use a comma-separated list with no spaces:
             CLIENT_ORIGIN = https://your-app.vercel.app,https://ramachandratraders.com

  4. PUBLISHING THE APP (only when real customers need to log in)
     OAuth consent screen -> click "Publish App" -> confirm.

     With only the three basic scopes (email, profile, openid), publishing is
     INSTANT and requires no Google review. You will see a warning about
     verification — it applies to sensitive scopes, which this app does not use.

     After publishing:
       - Anyone with a Google account can sign in
       - The 100-test-user limit is gone
       - The 7-day token expiry is gone
       - Users may still see an "unverified app" interstitial they can click
         past. To remove that screen entirely you would need full brand
         verification, which requires a privacy policy page, a terms page, a
         domain you own and have verified, and a demo video. This is optional
         and usually not worth it for a portfolio or small business site.
